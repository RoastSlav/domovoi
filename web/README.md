# Domovoi web UI

React + TypeScript + Vite. Built into `web/dist` and embedded in the hub binary with the `embed-ui` feature (ADR 0006).

## Develop

The UI needs a hub to talk to. For UI work, the dev example hub is enough: it serves the real API over a temporary database, with fake agents for two hosts, a seeded incident and two proposed actions.

```sh
cargo run -p domovoi-hub --example dev_hub   # from the repository root; listens on 127.0.0.1:7420
```

It prints a one-time setup link. Press Enter in its terminal to fire another incident and watch it arrive live. It also runs the real agent server on 127.0.0.1:7421, so **Hosts → Add host** creates working enrollment invites with the hub's real fingerprint.

Then, in `web/`:

```sh
npm ci
npm run dev          # http://localhost:5173, proxies /api and /hooks to the hub on 127.0.0.1:7420
```

Open the setup link with port 5173 instead of 7420, then create the admin account. Point the proxy at another hub with `DOMOVOI_HUB_URL=http://host:7420 npm run dev`.

## Embed in the hub

```sh
npm run build                                                           # writes web/dist
cargo run -p domovoi-hub --example dev_hub --features embed-ui          # serves it on :7420
cargo build -p domovoi --features embed-ui --release                    # the real binary
```

Without `embed-ui` the hub serves a short page explaining how to build the UI. With it, files under `/assets/` are cached for a year (their names change with their content) and `index.html` is never cached. Unknown paths outside `/api` and `/hooks` load the app, so client routes like `/incidents/<id>` work on reload.

## Check

```sh
npm run lint
npm run typecheck
npm test
npm run build
```

`cargo xtask ci --web` runs these, then lints and tests the hub with the built UI embedded.

## Layout

- `src/api/`: the typed client, query hooks per resource, and live events. The only code that talks to the network.
- `src/app/`: router, providers and the page frame.
- `src/components/`: shared UI (badges, dialogs, Markdown, times).
- `src/features/<feature>/`: pages and their parts.
- `src/test/`: test helpers. Tests mock `src/api/client` with `src/test/apiMock.ts`, never the network.

## API types

`src/api/openapi.json` is generated by the hub (`cargo xtask openapi`) and `src/api/schema.d.ts` by `npm run gen:api`. Never edit either by hand; CI fails if they are stale.

Only files in `src/api/` may talk to the network or import the generated types. Features use the hooks and the types re-exported from `src/api/types.ts`.

The client adds the session's `X-CSRF-Token` to every request that is not a read. On a 401 it sends the user to `/login`, or to `/setup` while no account exists.
